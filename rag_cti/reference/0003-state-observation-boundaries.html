State / Observation 边界速查

这页是第二课的压缩版：用来快速判断一个对象到底是控制状态、证据权威、边界记录、观测事件，还是模型可见投影。

一句话

Runtime state 解释这次运行如何推进；EvidenceLedger 证明答案基于什么证据；Observation 记录工具边界发生了什么；Event 让过程可观测；Context 只是给模型看的投影。

对象边界

对象负责什么不要放什么
RuntimeDeps 可复用服务和 provider policy。 per-run reasoning state、ledger、branch report、final answer。
RuntimeInvestigationState iteration、tokens、progress、sufficiency、stop reason、observations、events。 长期记忆、provider client、完整证据正文。
RuntimeObservation 一次工具边界的结构化结果：status、payload、delta、model-visible text。 最终答案、全局路由裁决。
RuntimeEvent trace/eval 友好的事件摘要：tool_result、tool_error、invalid_tool_call。 完整 chunks/facts。
EvidenceLedger 本次运行的证据权威：chunks、facts、outlines、actions、real_id_set。 provider error、prompt transcript、route decision。
Prompt / Context 从 state/ledger 渲染给模型看的当前工作视图。 唯一 truth source。

五个判断

看到这个现象优先判断
工具参数不合法 应该是 invalid observation，不应进入工具执行。
预算或 deadline 不允许执行 应该是 rejected observation，而不是 tool error。
模型没有提出工具调用 应该有 no_action observation/event，方便解释 run 为何收束。
只完成 entity resolution 可能是 setup progress，不是 citable evidence。
答案引用了 ID 去 EvidenceLedger 的 real_id_set 校验，不看 prompt 文本。
