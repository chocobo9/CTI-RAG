Lesson 05 · Grounding

Citation / Grounding / Faithfulness：把“有引用”拆成多个质量问题

第五课讲证据到答案之间的质量边界。一个答案可以带 citation，但仍然不 faithful；可以 grounded，但 evidence coverage 不充分；可以语言流畅，但关键 claim 没有证据支持。我们要把这些概念拆清楚。

先看全局：本课在地图哪里

第四课建立了 EvidenceLedger：本次 run 的证据权威。现在我们进入 Evidence and Trust 区域，问一个更靠近最终答案的问题：答案文本如何被证据约束？哪些检查是确定性的，哪些判断仍然需要 LLM-as-judge 或 eval？

Citation

答案中显式引用证据 ID。citation guard 至少要检查引用 ID 是否真实存在于本次 ledger。

Grounding

答案中的 claim 是否能追溯到 ledger evidence。它关心 claim 与证据之间的支撑关系。

Faithfulness

答案是否忠实于证据，没有夸大、改写、拼接出证据不支持的结论。

Sufficiency

已有证据是否足够覆盖用户问题需要的关键 facet。它决定是否继续 gather 或 stop。

本课核心胜利：你能看到“答案有引用”时立刻追问：引用 ID 是否真实？claim 是否由引用支持？答案有没有超出证据？证据是否覆盖了问题所需范围？这四个问题不是同一个。

学习目标：四个概念不能混

1

能区分 citation validation、grounding、faithfulness、sufficiency，各自回答的问题不同。

2

能解释 deterministic guard 和 LLM-as-judge 的边界：前者能查 ID，后者更适合评估 claim 支撑和覆盖。

3

能读懂 CTI-RAG 中 answer synthesis、citation guard、sufficiency verdict、conflict surfacing 的责任分工。

核心概念一：citation guard 是必要但不充分

Citation guard 最适合做确定性检查：答案里出现的 citation id 是否属于本次 ledger 的 real_id_set。如果不属于，就可以确定它是 hallucinated citation、旧证据引用或格式错误引用。

但它不能证明 claim 正确。举个简单例子：ledger 里确实有 chunk_apt29_1，答案引用它说“APT29 使用 T1059”。如果这个 chunk 只说了 APT29 的别名，没有提 T1059，那么 citation ID 真实，但 claim 仍然 ungrounded。

概念判断：citation validation 证明“引用对象存在”；grounding 才问“引用对象是否支持这句话”。

核心概念二：grounding 与 faithfulness 的差别

这两个词经常一起出现，但工程上可以这样区分：

概念核心问题例子常用检查
Grounding claim 是否能落回证据。 答案说 technique X，被引用 fact 明确支持。 claim-evidence matching、citation coverage、judge。
Faithfulness 答案是否忠实表达证据，没有额外扩张。 证据说“可能使用”，答案没有写成“确定使用”。 LLM-as-judge、人工 golden set、反例回归。

grounding 更像“有没有证据支撑”，faithfulness 更像“有没有背叛证据”。一个答案可能引用了相关证据，但仍然把证据强度写过头；这就是 faithfulness 问题。

核心概念三：sufficiency 决定继续还是停止

Sufficiency 不是答案质量的全部，它更像 gather loop 的 stop gate。它问：现有 ledger 是否足够回答用户问题？如果问题是“比较两个 actor 的 technique overlap”，只找到一个 actor 的证据，局部 claim 可以 grounded，但整体 evidence 仍不 sufficient。

常见误解

误解为什么不对更好的理解
“有 citation 就是 grounded。” citation ID 真实，不代表引用内容支持 claim。 citation validation 是 ID 层；grounding 是 claim-evidence 层。
“faithfulness 和 factual correctness 一样。” faithfulness 只相对于给定证据。答案可能忠实于错误证据，也可能事实正确但不由本次证据支持。 评估时要说明参照物：evidence、world truth、gold answer。
“sufficiency judge 说够了，答案就一定好。” sufficiency 是 gather stop 的判断，不替代 synthesis 和 citation/faithfulness 检查。 stop gate 和 answer quality gate 要分开。
“LLM-as-judge 可以替代 deterministic guard。” ID 是否存在是确定性问题，用代码查更可靠。 确定性 guard 查可形式化规则，judge 处理语义支持和覆盖。
“dropped citation count 越低，答案越可信。” 它只说明 hallucinated citation 少，不说明 claim-level support 强。 把 dropped count 当一个诊断信号，而不是总质量分。

读代码时问什么

审计问题你在找什么
答案的 evidence context 从哪里来？ 是否来自 ledger union/facts，而不是模型自由回忆。
citation ID 如何解析和验证？ 是否和 ledger real_id_set 相交；不存在的引用是否被丢弃并计数。
sufficiency 的输入是什么？ judge 是否看到 evidence view、last draft、coverage gaps，而不是凭空判断。
stop reason 如何暴露？ 停止是 sufficient、no_progress、budget、timeout 还是 parse fallback。
冲突证据如何进入答案？ 系统是否 surfaced conflicts，而不是自动消解或隐藏。
eval 测的到底是哪一层？ citation guard 测 ID，faithfulness eval 测语义忠实，retrieval eval 测候选证据，不要混成一个分数。

练习：不要把四个门混成一个词

1. Citation validation 最能确定性证明什么？

2. 答案引用真实 chunk，但该 chunk 不支持 claim，这是哪类问题？

3. 证据说“可能使用”，答案写成“确定使用”，主要是什么问题？

4. 只查到一个 actor，却回答两个 actor 的比较题，主要缺什么？

5. 为什么 deterministic guard 适合查 citation ID？

6. LLM-as-judge 更适合处理哪类问题？

7. dropped_citation_count 表示什么？

8. Sufficiency judge 的 next_action 应该怎么理解？

9. 冲突 evidence 最好的处理方式是什么？

10. 最准确的总结是哪一句？

本课小结

Citation validation、grounding、faithfulness、sufficiency 是四个不同问题。citation guard 可以确定性地过滤 ledger 外引用；grounding 检查 claim 是否被 evidence 支持；faithfulness 检查答案有没有背离证据；sufficiency 判断证据是否覆盖用户问题。下一课进入 supervisor：当一个问题需要多分支 gather 时，谁来协调 worker、谁来合并 ledger、谁来写最终答案。
