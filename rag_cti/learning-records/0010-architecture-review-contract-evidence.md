# Architecture Review Contract Evidence

The final learning outcome is architecture evaluation: design intent, runtime contract, code evidence, verification evidence, residual risk.

Teaching preference:
- Do not start from code aesthetics.
- Start from public API and runtime contract, then map to implementation and tests.
- Use the course vocabulary to evaluate boundaries: control/data plane, action/observation, ledger/trace, validated/legacy supervisor, citation/grounding/faithfulness.
- A good review must include strengths, concrete evidence, gaps, tests/eval coverage, and next risks.

Quality check:
- Exercises must ask for review judgments, not just definitions.
- Feedback should explain why each judgment supports or weakens the architecture.
