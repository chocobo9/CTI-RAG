## 2. Candidate Models

Three models were evaluated on the local CTI corpus per Phase 3a of the revised implementation plan.

### BAAI/bge-m3 *(configured production default)*

BGE-M3 from BAAI is the primary candidate. It supports dense, sparse, and multi-vector retrieval from a single checkpoint and leads the MTEB leaderboard across multilingual and domain-specific benchmarks. Well-suited for a corpus that mixes English technical prose (ATT&CK), semi-structured JSON (OTX pulses), and varied threat report formats. Also the value currently set as `embedding_model` in `config.py`.

### thenlper/gte-large

GTE-Large (General Text Embeddings, Alibaba DAMO Academy) achieves strong MTEB English retrieval scores at 1024 dimensions. Included as a validated alternative. Its higher dimensionality preserves fine-grained semantic distinctions between closely related ATT&CK subtechniques that smaller-dimension models collapse (e.g. T1055.001 vs T1055.012).

### nomic-ai/nomic-embed-text-v1.5

Fully open-source (Apache 2.0). Supports Matryoshka dimensionality reduction (64–768) and is optimised for long-context documents up to 8192 tokens, which benefits lengthy CTI PDF sections and verbose OTX pulse descriptions. Requires `trust_remote_code=True` when loading via `SentenceTransformer`.

### Voyage-2 *(deferred — budget-dependent)*

Proprietary API model from Voyage AI. Not included in the default bakeoff run because it requires a separate client and incurs per-token cost. Evaluate separately if budget allows.

## 3. Evaluation Methodology

### Corpus

- Sources: `data/processed/mitre.jsonl` + `data/processed/otx.jsonl`
- Sample size: 200 chunks (configurable via `--sample-size`)
- Seed: 42

### Query generation

Queries are generated by a Groq Llama model using a fuzzy CTI analyst prompt. Each query intentionally describes the "vibe" of the threat rather than repeating exact technical identifiers from the chunk — probing real-world retrieval robustness over keyword matching.

20 gold (query, chunk) pairs are generated from the first 20 corpus chunks. The gold chunk position is known, so retrieval success is scored exactly.

### Metrics

| Metric | Definition |
|---|---|
| **Recall@5** | Fraction of queries where the gold chunk appears in the top-5 results |
| **MRR** | Mean Reciprocal Rank — average of 1/rank across all queries |
| **Seconds per query** | Query encoding time divided by number of queries |

All models embed with L2-normalised vectors; cosine similarity is computed as a dot product.

### Selection rule

Models are ranked by `(Recall@5 desc, MRR desc)`. The top-ranked model is selected, subject to its latency being acceptable for the target deployment environment.

## 5. Risks and Mitigations

| Risk | Mitigation |
|---|---|
| Small evaluation set (20 queries) biases results | Re-run with `--n-queries 50 --sample-size 500` for higher confidence |
| LLM-generated queries may be too easy or too hard | Audit `queries` array in JSON; regenerate with `--seed <other>` if quality is poor |
| `nomic-embed-text-v1.5` requires `trust_remote_code` | Add `trust_remote_code=True` to `Embedder._load()` before evaluating this model |
| Latency measured on CPU may not reflect GPU deployment | Re-run with `--device cuda` on target hardware |
| Corpus sample may under-represent PDFs | Supplement with `--sources mitre otx pdfs` for a fuller picture |

```bash

python scripts/embedding_bakeoff.py --device cuda

# Extended run for higher confidence
python scripts/embedding_bakeoff.py --sample-size 500 --n-queries 50 --top-k 10
```
